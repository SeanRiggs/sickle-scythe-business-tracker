# v5.4 candidate acceptance

Historical v5.4 checks. For the current candidate, use [v5.5 acceptance](V5.5-ACCEPTANCE.md).

This candidate retains vanilla JavaScript, direct PKCE and OneDrive. It does not move hosting or migrate production records. Tests use fictional data only.

## Automated checks

Run from the repository root:

~~~sh
node --check app-config.js
node --check tracker-v543.js
node --check service-worker.js
node --test tests/*.test.cjs
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install --with-deps chromium webkit
node tests/browser.cjs
BROWSER_ENGINE=webkit PW_TEST_SCREENSHOT_NO_FONTS_READY=1 node tests/browser.cjs
node tests/acceptance.cjs
BROWSER_ENGINE=webkit NETWORK_MODE=server PW_TEST_SCREENSHOT_NO_FONTS_READY=1 node tests/acceptance.cjs
python3 scripts/check_public_files.py
python3 scripts/package_release.py
~~~

Browser tests cover desktop, 390×844, 360×640, 640×360, rotation with a sale draft and a reduced-height dialog. Emulation does not prove physical iPhone keyboard or installed-PWA behavior. The network harness mocks Graph and uses no production credentials.

## Manual release gate

- Inspect portrait and landscape screenshots.
- Rotate an actual phone with an unsaved sale. Check keyboard, Save/Cancel and larger text.
- Verify historical totals before editing.
- Review receipts and invoices privately; never attach customer documents to public PRs.
- On a fictional installation, cancel edits, receive multiple PO lines and import malformed CSVs; confirm all-or-nothing behavior.
- Cancel a restore preview, then restore a fictional backup. Reload and confirm uploads stay paused.
- Verify fresh-account creation, account mismatch and reconnect with your own test registration. Creation is disabled in the owner configuration.
- Check branding, product IDs, statements, credits, partial payments, refunds and void history.
- Keep backups before deployment. Verify version, cloud status and totals afterward. Never rerun historical repairs or migrations.

### Retained returns and search checks

Use fictional records in an isolated copy. Create one two-unit invoice totaling $520 with a $265 payment. Search for it, choose Return items, enter quantity 1 and reduction $255 with resellable stock and an actual date/reason. Cancel first to verify no changes. Confirm afterward: original invoice and payment remain intact, net invoice is $265, due is $0, and one unit returns to inventory. Reload and verify the saved return. Open invoice, payments, receipt, and return history directly from search.

Test a return larger than the balance: explicit Hold credit confirmation is required; cash remains unchanged. Test excessive quantity/amount, missing fields, an incorrect return reversal, and reversal after credit was refunded/applied. Confirm dated report reductions, invoice/statement summaries, CSV exports, unknown-field preservation, and offline reload/reconnect. Repeat on phone portrait and landscape. Do not repeat a return already handled by an earlier invoice correction.

### v5.4.3 purchasing and connected records

Use a fictional manufacturer with $260 approved unused warranty credit. Enter 20 units at $200 each, $200 shipping, $25 fees and $150 credit. The preview must show $4,075 net cost and $110 credit left. Save: stock must not increase. Follow Order details → View claim → View order and verify the allocated amount. Receive five units: inventory increases by five and the order shows 15 remaining. With no earlier purchases, the received stock's estimated cost is $203.75 each.

Create a second unreceived order using $50. Cancel it with a reason: its $50 returns to the source claim, the first order's $150 remains used, and the cancelled order/links stay in history. Repeating cancellation must not release more credit. A legacy order without links or an order with received stock must stop and explain the reconciliation needed.

Try credit above gross cost and above available claim credit, a different manufacturer's product, fractional quantities and an edit below the allocated credit. Verify no records change. Enter a $20.50 payment on a new sale and confirm the browser accepts the cents. In a customer profile, open payment editing and a receipt directly. Reload, then find an order by its supplier reference. Test storage-quota rollback and malformed cloud credit links with fictional fixtures.
