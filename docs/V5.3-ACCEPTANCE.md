## Acceptance checklist

Use fictional records in an isolated test profile first:

- [ ] Partial payment: 100 received against 290 leaves 190 due.
- [ ] Overpayment: 500 received against 290 retains 500 cash and creates 210 credit.
- [ ] Edit amount/date/method/reference/notes; original and new values appear in History.
- [ ] Apply 60 credit to another invoice; cash stays unchanged, available credit becomes 150.
- [ ] Attempt to reduce the original payment below already-used credit; the app blocks it with instructions.
- [ ] Reverse the credit transfer; both entries become void together, then correct the original payment.
- [ ] Refund part of the credit; net cash and available credit decrease appropriately. Edit or void the refund with an audit reason as applicable.
- [ ] Cancel payment editing; nothing changes. Reject zero, negative cash amounts, invalid dates, nonfinite amounts, and excess decimal precision.
- [ ] Generate a branded receipt, print/save PDF, confirm reference and notes, and distinguish recorded-after-save balances from current balances.
- [ ] Legacy payment receipts do not invent historical dates or balances. Voided receipts clearly say VOID.
- [ ] One customer's credit does not reduce another customer's debt. The same customer's unapplied credit and outstanding invoices are both visible.
- [ ] Units Sold sums quantities; Sales Transactions counts invoices. Voided records are excluded.
- [ ] Verify purchase receiving, warranty deductions, adjustments, partner-import duplicate protection, review disclosure, global-search focus, and Data Health.
- [ ] Disconnect network/session: warning stays prominent; local changes are retained. Reconnect using existing PKCE.
- [ ] Failed/unauthorized/missing-file cloud read performs no database write. Invalid cloud data never replaces the cache.
- [ ] Different device/cloud copies stop saving. Make a local backup before explicitly loading OneDrive. No automatic merge is promised.
- [ ] Close/reopen with pending changes, retry sync, and verify no local loss.
- [ ] Check desktop and phone layout, editor cancellation, receipt printing, and Back to Top.

## What tests cannot establish

Automated tests do not access the private OneDrive file, verify real Microsoft sign-in/token renewal, prove Graph CORS/conditional-write behavior on the owner's drive, validate printer output on physical devices, or reconcile historical financial records. Live synchronization acceptance is required before relying on this release. Conditional writes and comparison guards do not constitute multi-user collaboration; continue to use one editing device at a time.

Other legacy operational editors (purchase orders, expenses, warranty claims, inventory adjustments) retain their existing behavior and are not comprehensively redesigned by v5.3. Large attachments and a growing full audit history may exceed browser storage capacity; keep private backups and review any Not saved warning. This release does not purge historical Git contents or perform a comprehensive security audit.

If validation fails, stop editing and preserve both local and cloud copies. Restoring old source alone does not undo financial changes. Restore data only from a separately verified backup through a deliberate recovery process; never overwrite a newer cloud file just to clear a warning.
